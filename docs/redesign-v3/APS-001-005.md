# Purpose

This section defines the permanent principles governing every future decision made for AskChetna.

These principles are mandatory.

Whenever a requirement conflicts with one of these principles, the principle takes precedence unless a documented architectural exception has been approved.

These principles apply equally to:

- Product
- UX
- UI
- Engineering
- Content
- AI
- QA
- Marketing
- Android
- iOS
- Web

---

# Product Principles

---

## APS-PRN-0001

### User First

Every decision must improve the experience for the user.

Business goals should never reduce usability.

Questions to ask

- Does this improve the user's experience?
- Does this reduce effort?
- Does this increase clarity?
- Does this increase trust?

If the answer is "No", the decision should be reconsidered.

---

## APS-PRN-0002

### Clarity Before Cleverness

Users should immediately understand:

- where they are
- what this screen does
- what action they should take
- what happens next

Avoid:

Hidden interactions

Unclear icons

Decorative UI

Complex navigation

Ambiguous wording

---

## APS-PRN-0003

### Every Screen Has One Primary Goal

Each page should have one primary purpose.

Examples

Homepage

↓

Introduce platform

Tool Page

↓

Complete one task

Blog

↓

Educate

Dashboard

↓

Continue activity

Profile

↓

Manage account

Never overload a screen with competing objectives.

---

## APS-PRN-0004

### Every Component Must Be Reusable

Before creating a new component ask:

Can an existing component solve this problem?

If yes,

reuse.

If no,

create a reusable component.

Never build page-specific UI without strong justification.

---

## APS-PRN-0005

### Consistency Beats Variety

Avoid multiple visual solutions for the same interaction.

Examples

One button style

One input style

One dropdown style

One checkbox style

One modal style

One tooltip style

One accordion style

One loading style

One empty state style

The design language should feel unified.

---

## APS-PRN-0006

### Content Is The Product

Most visitors come to AskChetna for guidance.

Therefore

Content is more important than decoration.

Design exists to support reading.

Never distract users from the content.

---

## APS-PRN-0007

### Progressive Disclosure

Show information only when it becomes useful.

Avoid overwhelming users.

Large workflows should be broken into logical steps.

Examples

Good

Question

↓

Answer

↓

Recommendation

↓

Related Content

Bad

Everything shown immediately.

---

## APS-PRN-0008

### Predictability

Users should be able to predict:

Button behaviour

Navigation

Back actions

Loading

Errors

Success

Forms

Search

Predictability reduces cognitive effort.

---

## APS-PRN-0009

### Respect User Time

The platform should never waste attention.

Avoid:

Long onboarding

Unnecessary confirmations

Duplicate forms

Repeated questions

Forced navigation

Waiting without feedback

Every interaction should have purpose.

---

## APS-PRN-0010

### Respect User Privacy

Privacy should be obvious.

Never create uncertainty around:

Data collection

AI processing

Saved conversations

Personal information

Sensitive content

Users should always understand what is stored.

# AI Principles

The AskChetna platform is intentionally designed for AI-assisted development.

Therefore

AI systems should never invent.

They should assemble.

Allowed

Reuse

Compose

Refactor

Extend

Optimise

Document

Forbidden

Invent colours

Invent spacing

Invent typography

Invent components

Invent UX

Invent navigation

Invent brand language

Everything should come from APS.
