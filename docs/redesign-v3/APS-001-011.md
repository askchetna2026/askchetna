# Purpose

This document establishes the review framework that governs every future APS document.

No APS document, design, implementation or AI-generated output should be considered complete until it passes this review framework.

This section exists to guarantee long-term quality and consistency across the entire AskChetna ecosystem.

---

# Review Philosophy

The objective of review is not to approve work.

The objective is to eliminate ambiguity before implementation.

Every review should reduce the amount of interpretation required by:

- Designers
- Developers
- QA Engineers
- AI Coding Assistants
- Future Team Members

---

# Review Categories

Every APS document must pass the following reviews.

---

## Review 01

Business Review

Purpose

Validate business alignment.

Checks

- Product Vision alignment
- Product Mission alignment
- Business value
- User value
- Scope validation

Failure Example

Feature adds complexity without solving a business problem.

---

## Review 02

Product Review

Purpose

Validate product consistency.

Checks

- Product principles
- User journeys
- User problems
- Product goals
- Future roadmap compatibility

Failure Example

Feature contradicts Product Philosophy.

---

## Review 03

Design Review

Purpose

Validate visual consistency.

Checks

- Design Language
- Design Tokens
- Component usage
- Asset usage
- Typography
- Colour system
- Motion system

Failure Example

Introduces undocumented visual style.

---

## Review 04

UX Review

Purpose

Validate user experience.

Checks

Navigation

Task completion

Cognitive load

Interaction flow

Error handling

Empty states

Loading states

Accessibility

Failure Example

Users cannot complete the intended task efficiently.

---

## Review 05

Engineering Review

Purpose

Validate implementation quality.

Checks

Architecture

Scalability

Maintainability

Performance

Security

Documentation

Folder structure

Dependencies

Failure Example

Feature increases technical debt.

---

## Review 06

Cross Platform Review

Purpose

Validate Web, Android and iOS consistency.

Checks

Website

Android

iOS

Shared Design System

Platform-specific UX

Native behaviour

Failure Example

Android behaves like desktop website.

---

## Review 07

Accessibility Review

Purpose

Ensure inclusive design.

Checks

Keyboard

Screen Reader

Colour Contrast

Reduced Motion

Focus

Semantics

ARIA

Touch Targets

Failure Example

Critical interaction inaccessible.

---

## Review 08

Performance Review

Purpose

Protect user experience.

Checks

Rendering

Images

Bundle Size

Loading

Caching

Animations

Network Requests

Failure Example

Unnecessary rendering.

---

## Review 09

AI Readiness Review

Purpose

Ensure AI coding assistants can implement accurately.

Checks

Requirement IDs

Cross References

Implementation Notes

Traceability

Ambiguity

Machine Readability

Failure Example

AI must guess implementation.

---

## Review 10

QA Review

Purpose

Validate readiness.

Checks

Acceptance Criteria

Regression

Edge Cases

Test Coverage

Cross References

Failure Example

Requirements cannot be tested.
