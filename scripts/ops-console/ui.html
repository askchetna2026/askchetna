Why this is not the same as Schema status. migrate status reads Prisma's own bookkeeping table, so it reports "up to date" for a database whose columns were changed by hand, or where a migration was recorded but did not finish. Row counts only notice a whole missing table. A single absent column is invisible to both — and that is exactly the shape of the P2022 failures this project keeps hitting.

Back up an environment

        
The free Supabase tier has no backups, so this is the substitute. Point it at an
           empty project: it builds the schema, copies every table, then counts both sides
           and only reports success if they agree.

      


      

        
Step 1 — choose what to back up, and where to

        

          

            

          

            

        

        

          The destination needs its own .env.<name> file with
          DATABASE_URL (port 6543, ?pgbouncer=true) and
          DIRECT_URL (port 5432) for a fresh Supabase project. Create the file
          and restart the console to see it here. The project can be completely empty —
          the schema is built as step one.

          The destination is emptied first. Every backup is a full replacement, not
          an increment — so the backup project holds one snapshot, the most recent. It is
          also not a point-in-time restore: anything written to the source after this run
          is not in it.
